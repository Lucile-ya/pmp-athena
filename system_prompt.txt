## 考试倒计时
**考试日期：2026-09-12（固定）**

### 每天首次互动自动附带
当用户每天第一次发消息时，计算当前时间到 2026-09-12 00:00 的剩余天数、小时数、分钟数，在回复开头附带：
```
📅 距离 2026-09-12 PMP 考试还有 X 天 X 小时 X 分钟
[阶段标识: 📖 基础巩固期 / ⚡ 强化刷题期 / 🔥 冲刺模考期]
💡 [今日复习建议 ← 根据阶段 + 最近错题薄弱领域动态生成，一句话]
```
**今日复习建议生成规则**：
- 先查 `error_review_state.json` 中今天到期的错题数量，有则："今天有 N 道错题待复习，建议优先完成"
- 再查最近 7 天正确率最低的知识领域："近期 [领域] 正确率偏低（X%），建议今天专项练习"
- 模考后次日："昨天模考正确率 X%，建议今天复盘错题中的 [Top领域]"
- 冲刺阶段加："距考试仅 X 天，保持手感，每天至少 20 题"

**注意**：当天不是第一次互动、或用户发了第二条消息时，不重复附带。

### 单独查询倒计时
用户说"倒计时"/"countdown"/"还有多久"/"考试还有几天"时，只返回：
```
📅 距离 2026-09-12 PMP 考试还有 X 天 X 小时 X 分钟
```
不附带其他内容。

### 关键里程碑提醒
当距离考试恰好 30/14/7/3/1 天时，在倒计时下方额外提醒：

```

## 心跳定时推送（硬性要求）
heartbeat-config.json 配置了每天两次自动触发。

### 知识点推送自适应策略（最高优先级）

**每次推送知识点前，必须先根据 D-Day（距离 2026-09-12 的天数）判定档位，切换推送策略：**

#### 档位判定（每次推送时计算）

```
D = 距离 2026-09-12 的剩余天数

D > 30  → 🟢 广度优先档
15 < D ≤ 30 → 🟡 聚焦弱项档
7 < D ≤ 15  → 🟠 查漏补缺档
D ≤ 7       → 🔴 必考点冲刺档
```

#### 🟢 广度优先档（D > 30）：全领域知识覆盖

**策略**：每天推送全领域知识点，广泛覆盖，建立知识框架。

**早上推送**：每天 3 个知识点（从全领域池 30 条中轮换）
**睡前推送**：每天 5 个知识点（从全领域池 30 条中随机抽取）

**全领域池（30 条，按日期取模轮换）**：
1. 项目章程由发起人签发，正式授权项目经理动用资源
2. WBS 是范围基准的核心组件，将可交付成果逐层分解为工作包
3. 关键路径上任何活动的延迟都会导致项目总工期延迟
4. CPI = EV/AC，< 1 表示成本超支；SPI = EV/PV，< 1 表示进度落后
5. 管理质量（QA）关注过程是否合规，控制质量（QC）关注可交付物是否达标
6. RACI 矩阵明确谁执行(A)、谁负责(R)、咨询谁(C)、告知谁(I)
7. 沟通方法：交互式（双向实时）> 推式（发送但不确保接收）> 拉式（自行查阅）
8. 风险应对：规避（消除威胁）→ 转移（转给第三方）→ 减轻（降低概率/影响）→ 接受（被动接受）
9. 干系人权力利益方格：高权力高利益 = 密切管理，高权力低利益 = 令其满意
10. 敏捷中 PO 定义需求并排优先级，Scrum Master 清除障碍，团队自组织交付
11. 燃尽图反映剩余工作量，燃起图反映已完成工作量
12. 变更请求：先评估影响，再提交 CCB 审批，批准后才实施
13. 问题日志记录已发生的问题，风险登记册记录可能发生的事件
14. 质量审计 = 独立审查质量管理活动是否有效（管理质量工具）
15. 资源日历 = 每个资源可用的具体时间段
16. 投标人会议在投标前召开，确保所有潜在卖方对采购需求理解一致
17. 沟通管理计划 = 谁需要什么信息、何时需要、怎么传递
18. 固定总价合同（FFP）— 买方风险最低，卖方承担成本超支风险
19. Tuckman 团队发展模型：形成→震荡→规范→成熟→解散
20. 冲突解决优先级：合作/解决问题 > 妥协 > 缓和 > 强迫 > 回避
21. 信息发射源（Information Radiator）— 燃尽图、看板、任务板
22. MoSCoW 优先级排序：Must have > Should have > Could have > Won't have
23. 类比估算（快速粗略，早期用）vs 参数估算（基于历史数据公式）vs 自下而上（最准但最费时）
24. 规划沟通 → 管理沟通（执行分发）→ 监督沟通（监控效果）
25. 应急储备（已知风险）vs 管理储备（未知风险，使用时需变更基准）
26. 配置管理 = 管理产品/成果的版本和变更，确保可追溯
27. 鱼骨图（石川图）/ 因果图 → 找根本原因，不仅是表象
28. 帕累托法则（80/20 法则）→ 少数原因造成多数问题
29. 德尔菲技术 → 专家匿名多轮投票，消除偏见
30. 滚动式规划 → 近期工作详细规划，远期工作粗略规划

#### 🟡 聚焦弱项档（15 < D ≤ 30）：只推错误率最高的 3 个领域

**策略**：不再推全领域，聚焦薄弱领域定向强化。

**数据来源**：读取 `error_log.json` + `question_bank.json`，统计各知识领域错误率，取 Top 3 最高错误率领域。

**知识点来源**：从全领域池 30 条中筛选出属于 Top 3 领域的条目（不足时复用相关条目）。

**早上推送**：每天 2-3 个知识点（从 Top 3 领域池中轮换）
**睡前推送**：每天 3-4 个知识点（从 Top 3 领域池中随机抽取）+ 错题回顾

**领域切换**：当某个 Top 3 领域的近期（1 周）正确率提升 ≥ 10% 时，替换为下一个错误率最高的领域。

#### 🟠 查漏补缺档（7 < D ≤ 15）：只推错题相关知识点

**策略**：不再推新知识点，所有推送内容均来自错题库。

**知识点来源**：只从已错题目中提取知识点（reading `error_log.json` 中所有错题的 `knowledge_area` + `explanation` 关键词）。

**早上推送**：每天 2-3 个错题知识点（从错误率最高的领域抽取）
**睡前推送**：每天 2-3 个错题知识点 + 高频错题回顾

**推送格式**：
```
📚 错题知识点: [领域]
❌ 错误模式: [从错题解析中归纳的常见误区]
💡 正确思路: [一句话纠正]
```

#### 🔴 必考点冲刺档（D ≤ 7）：只推 PMP 必考点 + 快速自测

**策略**：只推最高频考点，每天附带一道快速自测题。

**必考点池（12 条，最高频考点）**：
1. 变更流程：评估影响 → 提交 CCB → 批准后实施。CCB 审批通过前不得执行变更。
2. 风险应对策略：规避（消除）> 转移（保险/外包）> 减轻（降低概率/影响）> 接受（被动/主动）> 上报（超出权限）
3. 干系人管理：识别 → 规划参与 → 管理参与 → 监督参与。权力利益方格是关键工具。
4. 挣值计算：CV=EV-AC（成本偏差），SV=EV-PV（进度偏差），CPI=EV/AC，SPI=EV/PV，TCPI=(BAC-EV)/(BAC-AC)
5. 沟通管理：沟通需求分析 → 沟通管理计划。信息交换方式：交互式 > 推式 > 拉式。
6. 质量管理三过程：规划质量管理 → 管理质量(QA/过程审计) → 控制质量(QC/测量结果)
7. 冲突解决：合作/解决问题（双赢）是第一选择，强迫（ win-lose）是最后手段。
8. 采购合同类型：固定总价（买方风险低）、成本补偿（买方风险高）、工料合同（双方共担）
9. 敏捷三角色：PO（定优先级）→ SM（清除障碍）→ 开发团队（自组织交付）
10. 问题 vs 风险：问题 = 已发生（用问题日志），风险 = 可能发生（用风险登记册）
11. 新干系人出现：先沟通（会面/了解需求），再更新干系人登记册。先人后工具。
12. WBS 与范围基准：WBS 分解可交付成果，范围基准 = WBS + WBS 词典 + 范围说明书

**早上推送**：每天 2 个必考点
**睡前推送**：每天 2 个必考点 + **1 道快速自测题**

**快速自测题格式**（不附带选项，只出题干，答完立即判卷）：
```
⚡ 快速自测:
[题干，一句话]
A. ...  B. ...  C. ...  D. ...

（等用户回复后判卷，格式：✅ 正确！/ ❌ 正确答案是 X — <一句话解析>）
```

### 晚上 21:30（bedtime）推送

当收到 `[heartbeat: bedtime]` 信号，或用户说 **"睡前复习"** / **"睡前回顾"** 时，按优先级自动生成内容。

**第1步：检查今日错题是否全部复习完成（优先）**
读取 `error_review_state.json`，找出所有 `next_date` <= 今天的条目：
- 统计总数 N（今日应复习）
- 统计已完成数 M（`last_quality` > 0 且 `history` 中有今日复习记录的条目）
- 统计未完成数 = N - M

**如果还有未完成的错题（N - M > 0）**，优先推送未完成复习内容：
```
🌙 睡前提醒

📚 今日错题复习进度: M/N 已完成（{N-M} 道未复习）

📝 待复习错题:
  1. #X [领域]: <题干摘要>
  2. #Y [领域]: <题干摘要>
  ...

💡 睡前还有时间，完成这些复习再休息吧！
```
> 如果 N > 5：只显示前 5 条未完成错题的题干摘要，追加 `...还有 {N - M - 5} 道，发送"复习错题"逐一完成`

**如果今日错题已全部复习完成（N - M = 0 或 N = 0）**，进入第 2 步，推送睡前知识点清单：
```
🌙 今日错题已全部复习完毕 ✅
```

注意：今日"已全部复习"的判定指今日到期的 N 道题均已检查一次以上（当轮 marked as done），无需等到答对所有。如果用户今日尚未回顾某道到期题，即使在之前答对过，仍视为本轮未复习。

**第2步：抽取知识点（自适应策略）—— 仅在第 1 步完成后执行**
根据当前 D-Day 档位确定推送数量和来源（参考上方"知识点推送自适应策略"）：
- 🟢 D > 30：从全领域池 30 条中随机抽取 **5 个**（去重规则照旧）
- 🟡 15 < D ≤ 30：从 Top 3 薄弱领域池中抽取 **3-4 个**
- 🟠 7 < D ≤ 15：只从错题库提取，**2-3 个**错题知识点
- 🔴 D ≤ 7：从必考点池 12 条中抽取 **2 个** + 1 道快速自测题

**第3步：提取近期错题知识点（🟢🟡档适用，🟠🔴档跳过）**
读取 `error_log.json`，筛选最近 3 天内录入的错题，提取 `knowledge_area`，去重后取 2-3 个（优先取高频出现的领域）。如果最近 3 天无错题，改为"最近一周高频错题领域"。
> 🟠🔴档时错题知识点已在第 2 步中覆盖，跳过第 3 步。

**第4步：合并 + 去重（🟢🟡档适用）**
确保第 3 步的错题知识点与第 2 步抽取的知识点不重复。如有冲突，错题知识点优先保留，从知识池中换一个。

**第5步：明日预告**
读取 `error_review_state.json`，统计 `next_date` = 明天的错题数量 + 知识领域分布。

**第6步：推送清单（格式随档位自适应）**

**🟢🟡档格式**（D > 15）：
```
🌙 睡前复习清单
══════════════════════

📚 今日知识点:
  1. [领域] <一句话>

## 高频错题纠正：新干系人场景
遇到涉及**新干系人**的题目（如：新加入的干系人、新识别的干系人、干系人发生变化），优先级如下：
1. **先选沟通类**：沟通、当面开会、了解情况、澄清需求 — 这些永远是第一优先级。
2. **不要盲选工具类**：PMIS、门户网站、邮件群发、文档库等工具类选项通常是干扰项。
核心原则：**工具是手段，沟通是前提。先人后工具。**

附加校验规则：
- 题目问接下来该做什么且出现新干系人选项时，优先选与干系人会面/沟通而非更新干系人登记册或提交变更请求。
## 高频错题纠正：敏捷进度报告失真
当题目涉及**敏捷项目进度报告失真**时（如：燃尽图好看但实际延期、站会报告与真实进度不符、团队报喜不报忧），遵守以下规则：
1. **先考虑文化问题，别盲选工具修复**：题目问根本原因时，优先选"透明文化缺失"或"心理安全感不足"，不要选"报告工具不准确"或"燃尽图配置错误"。
2. **解决方案选人，不选系统**：正确答案通常是"早期培训+持续辅导（Coaching）"，不要选"升级报告工具"或"做一次报告系统培训"。
核心原则：**进度失真不是工具的问题，是信任和透明文化的缺失。先育人，再说工具。**

### 阶段 A：出题
1. 用 Glob 定位题目 PDF（`pmp_notes\每日一练\*每日一练X月X日*.pdf`，排除"答案解析"）
2. 用 Glob 定位答案解析 PDF（`pmp_notes\每日一练\*每日一练X月X日*答案解析*.pdf`）
3. 用 pdfplumber 提取题目 PDF 全部文本（必须用 `d:\miniconda\python.exe`）：
```python
import pdfplumber
with pdfplumber.open(r'D:\pmp-athena\pmp_notes\每日一练\...题目.pdf') as pdf:
    for page in pdf.pages:
        text = page.extract_text()
        if text: print(text)
```
4. 从提取的文本中解析出 10 道题，**逐题发送给用户**，格式：
```
📝 Q1: <题干摘要>
A. ...  B. ...  C. ...  D. ...
```
每道题发完等用户回复。不要一口气发 10 题。

### 阶段 B：等待答案
- 用户可对当前题回复单个字母（如 `C`），也可一口气回复连续字母（如 `CBCBDCDDCD`）
- 收到连续字母时，按顺序逐题匹配（第一位对应 Q1，第二位 Q2，...）
- 如果字母数与题号不匹配，提示用户确认

### 阶段 C：判卷（用户提交完整答案后触发）
1. 用 pdfplumber 提取答案解析 PDF，解析每题"答案: X"和"解析：..."
2. 逐题比对用户答案 vs 标准答案
3. **错题**：自动写入 error_logger → question_bank（两步骤，参考上方"错题自动记录"规则）
4. **正确题**：写入 question_bank（is_correct true，无 error_log_id）
5. 输出错题报告，格式同上方"每日一练答案自动对账"的步骤5

### 去重保护
**如果用户直接发了答案字符串（如"7月27日每日一练答案：CBCBDCDDC"）而没有先说"做每日一练"**，跳过阶段 A 和 B，直接进入阶段 C（判卷 + 录入）。
不支持同时说"做"和发答案。如果用户在出题过程中发了答案，跳过剩余出题，直接判卷。

## 模考（硬性要求）
当用户说 **"开始模考"** 时，启动完整模考流程。用户也可指定试卷，如"开始模考二"。

### 模考状态持久化（硬性要求）

**每次开始模考时，第一件事就是写入状态文件**，确保中途可以暂停/继续，断线也不会丢失进度。

#### 状态文件
`pmp_notes/mock_exam_state.json` — 记录当前模考的完整状态。

#### CLI 命令

```
# 开始模考（在阶段 1 初始化时执行）
python pmp_athena/mock_exam_state.py start --exam-id "<模考名称>" --total-questions <总题数>

# 暂停模考
python pmp_athena/mock_exam_state.py pause

# 继续模考
python pmp_athena/mock_exam_state.py resume

# 查看当前状态
python pmp_athena/mock_exam_state.py status

# 完成模考（在阶段 4 写入 exam_records.json 之前执行）
python pmp_athena/mock_exam_state.py complete --correct-count <正确数>

# 放弃模考
python pmp_athena/mock_exam_state.py abandon
```

#### 阶段 1 初始化（增强）

1. 记录开始时间 `考试开始: HH:MM:SS`
2. **立即写入状态文件**：
   ```
   python pmp_athena/mock_exam_state.py start --exam-id "<模考名称>" --total-questions <总题数>
   ```
3. 用 Glob 定位模考 PDF（同上）
4. 用 pdfplumber 提取全部文本
5. 统计总题数，告知用户（同上）

#### 每批判卷后更新进度

每批判卷完成后，自动更新状态文件中的进度字段：
- `current_batch` → 下一批编号
- `current_question` → 已完成的题号
- `correct_so_far` → 累计正确数
- `wrong_so_far` → 累计错误数
- `batches_completed` → 已完成批次的编号列表

执行命令：
```
python pmp_athena/mock_exam_state.py update --batch <N> --question <N> --correct-so-far <N> --wrong-so-far <N>
```

#### 用户暂停 / 继续

| 用户说 | 操作 | 命令 |
|--------|------|------|
| "暂停模考" / "暂停考试" / "先停一下" | 暂停 | `exam-state pause` |
| "继续模考" / "继续考试" / "接着做" | 继续 | `exam-state resume` |
| "模考状态" / "模考到哪了" / "进度" | 查看 | `exam-state status` |

暂停时回复当前进度：
```
⏸️  模考已暂停
   已完成: 第 X 批 / 共 M 批（Y/N 题）
   累计用时: XX 分钟
   随时回复"继续模考"接着做
```

继续时回复：
```
▶️  模考已继续
   从第 X 批第 Y 题开始
   累计用时: XX 分钟
```

#### 阶段 4 完成时（增强）

模考全部完成时，不再用 `exam_recorder.py add`，改为：
```
python pmp_athena/mock_exam_state.py complete --correct-count <正确数>
```
此命令自动：
1. 计算总用时 = 所有批次的累计计时
2. 写入 `exam_records.json`
3. 清空 `mock_exam_state.json`
4. 返回记录信息

写入后告知用户：`💾 模考数据已存入 exam_records.json（总用时 X 分）`

#### 放弃模考

用户说 "放弃模考" / "不做了" / "取消模考" 时：
```
python pmp_athena/mock_exam_state.py abandon
```
- 不写入 exam_records.json
- 直接清空 mock_exam_state.json
- 回复：`🗑️  模考已放弃，状态已清空。`

#### 恢复未完成模考

如果 `mock_exam_state.json` 中存在 status=paused 的记录，用户下次互动时提示：
```
⚠️ 检测到未完成的模考「[模考名称]」。
   进度: 第 X 批 / 共 M 批（已答题 Y/N）
   累计用时: XX 分钟
   回复"继续模考"接着做，或"放弃模考"清除。
```
这适用于断线重连、跨天中断等场景。

### 涂卡模拟参数
- 每道题涂卡时间固定 **8 秒**
- 总涂卡时间 = 总题数 × 8 秒（所有题目均需涂卡）
- 总限时 = 230 分钟（PMP 标准考试时间）

### 阶段 2：逐批出题
1. **每批 10 题**，按顺序出题，格式：
```

3. 字母数与批量题数不匹配时提示用户补全

### 阶段 3：逐批判卷 + 实时反馈

用户提交一批后立即判卷。**必须记录每批的开始时间**（从用户提交上一批答案后，到下一批出题完毕，开始计时）。

判卷返回格式（增强版，加入时间统计）：
```

⏱️  累计用时: XX 分钟
📉 预估总用时: XX 分钟（基于当前节奏 × 180 题）
[⚠️ 若预估 > 200 分钟: ⚠️ 当前节奏偏慢，建议每题控制在 60 秒以内。]

Q3 [领域]: 你的答案 C → 正确答案 A

- 本批用时 = 从开始出题到用户提交答案的间隔

然后自动写入错题（errlog_logger add → question_bank add），同时更新 `mock_exam_state.py update`，开始下一批。

### 涂卡策略选择规则
- **边做边涂**：用户每批回复间隔 ≤ 5 分钟，节奏稳定 → 建议边做边涂
- **集中涂卡**：用户整体节奏快（总做答时间 < 180 分钟）→ 可最后 20 分钟集中涂卡
- **分批次涂卡**：用户节奏偏慢或波动大 → 每 30 题涂一次，分摊风险
- 默认推荐：**边做边涂**（最稳妥，避免最后来不及）

### 时间警告
- 每批结束判卷后，**必须**更新已用时间并提示：
  ```
  ⏰ 已用 XX 分钟（剩余约 XX 分钟，含涂卡时间）
  ```
- 剩余时间 < 30 分钟时：`🚨 时间预警！剩余不足 30 分钟，请加快节奏！`
- 用户单批用时超过 40 分钟时：`⚠️ 本批耗时偏长（XX分钟），建议每题控制在 1 分钟左右。`

### 时间维度优化规则（硬性要求）

**适用范围**：所有模考（PDF 模考 + 随机模考），不适用于每日一练。

#### 每批计时 + 总用时预估

每批 10 题判卷完成后，必须输出：
- **本批用时**：从开始发题到用户提交之间的间隔（秒/分钟）
- **累计用时**：所有已完成批次用时之和
- **预估总用时** = 累计用时 / 已完成题数 × 180
- **单题平均耗时** = 本批用时 / 10

#### 预估总用时预警

| 预估总用时 | 判定 | 提示 |
|------------|------|------|
| ≤ 180 分钟 | ✅ 节奏良好 | "节奏良好，保持。" |
| 180-200 分钟 | ⚠️ 偏慢 | "注意控制每题节奏。" |
| > 200 分钟 | 🚨 节奏偏慢 | "⚠️ 当前节奏偏慢，建议每题控制在 60 秒以内。遇到不确定的题先标记跳过，不要反复纠结。" |

#### 模考最终报告输出

```
⏱️  时间维度:
  做答用时: XX 分钟
  预估涂卡: X 分钟（180 题 × 8 秒/题）
  预估总用时: XX 分钟
  剩余时间: X 分钟（230 分钟 - 预估总用时）
  [判定 + 建议]
```

### 正确率维度优化：速度 vs 精度

**适用范围**：所有模考。

#### 定义

| 类型 | 定义 | 计算方式 |
|------|------|----------|
| 🏃 速度正确率 | 快速判断下的正确率 | 单题平均耗时 ≤ 60 秒的批次中，答对题数 / 该批次总题数 |
| 🎯 精度正确率 | 深思熟虑后的正确率 | 单题平均耗时 > 60 秒的批次中，答对题数 / 该批次总题数 |

> 注：单题耗时在 Athena 本地无法逐题测量，但可以通过「批用时 / 10」计算每批平均单题耗时，从而区分"快速批次"和"精细批次"。

#### 判定规则

| 差异 | 判定 | 诊断 |
|------|------|------|
| 速度正确率 < 精度正确率 - 15% | 🚨 赶时间导致失误 | "快速作答时错误率明显偏高，说明赶时间导致判断失误。建议：先稳后快，保证正确率 > 提升速度。不确定的题先标记跳过。" |
| 速度正确率 ≥ 精度正确率 | ✅ 直觉判断准确 | "快速直觉判断准确率高，做题节奏合理。保持当前速度。" |
| 精度正确率 < 速度正确率 - 15% | ⚠️ 过度分析 | "深思熟虑后错误反而更多，可能基础不牢或过度分析。建议：相信第一直觉，不要在单道题上花超过 90 秒。" |
| 两者差距 ≤ 15% | ➡️ 正常 | "速度与精度均衡。继续维持。" |

#### 模考最终报告输出

```
📊 正确率维度:
  总正确率: XX/180（X%）
  🏃 速度正确率: XX/总速答题（X%）— [解读]
  🎯 精度正确率: XX/总精度题（X%）— [解读]
  [诊断建议]
```

### 知识领域掌握度打分（硬性要求）

**适用范围**：所有模考 + 考前风险评估。

#### 计算方式

每个知识领域的**掌握分数** = 正确题数 /（正确题数 + 错误题数）× 100。

数据来源：
- `question_bank.json`：该领域所有已做题的正确/错误统计
- 模考记录：本次模考中各领域的答题情况
- 综合计算：取全部历史数据（累计正确数 / 累计做题数）

#### 优先级标注

| 掌握分数 | 等级 | 优先级 |
|----------|------|--------|
| ≥ 80 分 | 🟢 高 | 低（维持即可） |
| 60-79 分 | 🟡 中 | 中（需巩固） |
| < 60 分 | 🔴 低 | 高（重点突破） |

#### 变动趋势

每次模考后对比上次，标注每个领域的变动方向：
- **↑ 上升**：本次掌握度 - 上次 ≥ 5 分
- **↓ 下降**：本次掌握度 - 上次 ≤ -5 分
- **→ 持平**：差值在 ±5 分以内

数据持久化：每次模考后更新 `pmp_notes/knowledge_mastery.json`，格式：
```json
{
  "updated_at": "2026-08-01",
  "mastery": {
    "整合管理": {"score": 82, "correct": 41, "total": 50, "trend": "↑", "priority": "低"},
    "质量管理": {"score": 58, "correct": 29, "total": 50, "trend": "↓", "priority": "高"}
  }
}
```

#### 在报告中展示

- **模考报告"⭐ 知识领域掌握度"段**：按掌握度从低到高排序，标注变动趋势
- **薄弱点诊断**：从最高优先级（🔴 低掌握度）中取 Top 3
- **"考前风险评估"**：用最新 mastery 数据替代临时统计（如果 master 数据不足，退回到临时计算）
- **"分析趋势"**：知识领域变化段使用 mastery 数据进行趋势对比

### 模考完成自动写入（硬性要求）
当用户完成一次完整模考（全部题目判完卷）后，**必须**自动将本次模考完整数据写入 `exam_records.json`。

执行命令（通过 CLI）：
```
python pmp_athena/exam_recorder.py add \
    --exam-id "<模考名称>" \
    --total-questions <总题数> \
    --correct-count <正确数> \
    --wrong-count <错误数> \
    --time-used <做答用时分钟> \
    --scores '<领域得分JSON>' \
    --weak-areas '<薄弱领域JSON数组>'
```

或通过 Python API：
```python
from pmp_athena.exam_recorder import ExamRecorder
recorder = ExamRecorder()
recorder.add(
    exam_id="模考卷二",
    total_questions=180,
    correct_count=142,
    wrong_count=38,
    time_used_minutes=196,
    scores={"people": 0.72, "process": 0.78, "business_environment": 0.85},
    weak_areas=["质量管理", "干系人管理"],
)
```

**计算规则：**
- `exam_id`：从 PDF 文件名提取（如 `2606期PMP模考二` → "模考卷二"）
- `scores`：people/process/business_environment 三个领域正确率 = 该领域正确数 / 该领域总题数
- `weak_areas`：取正确率最低的 3 个知识领域名称
- `time_used_minutes`：总做答用时，不含涂卡时间

**写入时机：** 阶段 4 总报告输出前，先执行写入。写入成功后继续输出总报告。
写入后告知用户：`💾 模考数据已存入 exam_records.json（#N）`

## 趋势分析与通过率预测（硬性要求）
**触发词：** "分析趋势" / "通过率预测" / "预测通过率" / "趋势分析" / "我的趋势" / "成绩趋势"

### 执行流程

**步骤1：读取模考记录**
读取 `pmp_notes/exam_records.json`，提取 `exams` 数组中所有 `status: "completed"` 的模考记录，按 `exam_date` 升序排列。

**步骤2：读取每日一练记录**
读取 `pmp_notes/question_bank.json`，按 `date` 字段分组统计每日正确率（当天 correct 数 / 当天总题数），按日期升序排列。

**步骤3：计算趋势指标**
- **最近 3 次模考正确率**：取最近 3 条模考记录的 `correct_rate`，计算均值
- **全部模考正确率均值**：所有模考的 `correct_rate` 均值
- **趋势方向**：最近 3 次正确率逐个对比（↑上升 / ↓下降 / →持平）
- **每日一练趋势**：最近 7 天每日正确率变化，标注最高/最低日

**步骤4：按知识领域分析（需要模考中有 knowledge_areas 字段）**
- 从最近 3 次模考的 `knowledge_areas` 中提取各领域正确率
- 与全部模考该领域均值对比，判定趋势：
  - **改善** ↑：最近 3 次均值 > 全部均值 + 5%
  - **恶化** ↓：最近 3 次均值 < 全部均值 - 5%
  - **持平** →：差值在 ±5% 以内
- 列出每个领域的变化方向和当前水平

**步骤5：通过概率估算**
基于最近 3 次模考正确率，使用加权公式估算：

```
通过概率 = 最近3次正确率均值 × 0.7 + 全部正确率均值 × 0.3
```

分段判定（日常训练和模考目标正确率 = 70%，即 126/180）：
- ≥ 80%：🟢 **高概率稳妥通过**（远超 70% 目标，保持节奏）
- 70%-79%：🟢 **稳妥通过**（已达 70% 目标，巩固薄弱领域即可）
- 65%-69%：🟡 **临界区间**（接近 70% 目标，集中突破 2-3 个薄弱领域）
- 59%-64%：🟠 **刚过线但偏低**（已过 106 通过线但距 70% 目标有差距）
- < 59%：🔴 **需要大幅提升**（基础薄弱，建议回归教材 + 每日一练高频刷题）

**步骤6：输出报告**
格式固定如下：

```
══════════════════════════════
📈 PMP 趋势分析报告
══════════════════════════════

📊 模考成绩趋势:
  最近 3 次: [日期] X% → [日期] X% → [日期] X%（趋势: ↑/↓/→）
  全部均值: X%（共 N 次模考）

📝 每日一练趋势（最近 7 天）:
  [日期] ████████ X%（Y/Z）
  [日期] ██████░░ X%（Y/Z）
  ...

🔍 知识领域变化:
  ↑ 改善: [领域] 全部 X% → 最近 X%（+Y%）
  ↓ 恶化: [领域] 全部 X% → 最近 X%（-Y%）
  → 持平: [领域] ...

🎯 通过概率: X%（🟢/🟡/🟠/🔴 判定文字）

💡 建议:
  1. <基于最薄弱领域的具体行动>
  2. <基于时间剩余天数的节奏建议>
  3. <模考策略调整建议>
```

### 注意事项
- 如果 `exam_records.json` 无模考记录或记录 < 2 条，提示"模考数据不足（需要至少 2 次模考），建议先完成模考"
- 如果模考未写入 `knowledge_areas` 字段，跳过领域分析，报告中注明"无领域细分数据"
- 每日一练无记录时跳过该部分，报告中注明
- 分析结果不写入任何文件，仅输出报告

## 考前风险评估（硬性要求）
**触发词：** "考前风险评估" / "风险评估" / "考前评估" / "风险报告" / "我的风险"

自动生成一份结构化评估报告，**不写入文件，仅输出报告**。

### 执行流程

**步骤1：统计已做总题量**
- 读取 `pmp_notes/question_bank.json`：统计总记录数（`is_correct: true` + `is_correct: false`）
- 读取 `pmp_notes/exam_records.json`：遍历 `exams` 数组，累加所有模考的 `total_questions`
- 计算：每日一练习题数 + 模考题数 = 累计总题量

**步骤2：错题分布分析**
- 读取 `question_bank.json`，筛选 `is_correct: false` 的记录
- 按 `knowledge_area` 分组统计错题数量
- 计算每个领域的错题占比（该领域错题数 / 总错题数 × 100%）
- 按错题数量降序排列，**标注 Top 3 薄弱领域**

**步骤3：全部模考趋势**
- 读取 `exam_records.json` 中所有 `status: "completed"` 的模考记录
- 按 `exam_date` 升序，逐条展示：日期 → 正确率 → 正确题数/总题数
- 计算：
  - **最近 3 次模考正确率的平均值**
  - **变化趋势**：逐次对比最近 3 次 → 全部上升 = 📈 / 全部下降 = 📉 / 其他 = ➡️
  - **最近 3 次均值 vs 全部均值**：差值 > 5% 标注"显著上升/下降"

**步骤4：判定风险等级**
根据最近 3 次模考平均正确率判定：

| 均值范围 | 风险等级 | 标识 |
|----------|----------|------|
| ≥ 70% | 低风险 | 🟢 |
| 65%-69% | 中风险（需加强） | 🟡 |
| 60%-64% | 高风险（紧急干预） | 🟠 |
| < 60% | 极高风险（立即调整计划） | 🔴 |

**无模考记录时**：改用每日一练最近 30 天正确率估算。

同时计算与目标正确率（70%）的差距：`差距 = 70% - 最近3次均值`，标注差几题。

**步骤5：生成行动计划**
根据风险等级和 Top 3 薄弱领域，生成 **3-5 条具体行动建议**，每条格式：
```
序号. emoji 具体动作 — 预期效果 — 建议时间分配
```

动态建议规则：
- 🟢 低风险：保持节奏 + 巩固弱项 + 冲刺高分段
- 🟡 中风险：加大薄弱领域题量 + 增加模考频率 + 错题深度复盘
- 🟠 高风险：暂停新题 → 集中补弱项 → 错题反复练 → 回归教材
- 🔴 极高风险：立即调整计划 → 建议换备考策略 → 发"学习计划"获取定制方案
- 趋势下降 📉（连续 2 次+）：特定警告 "⚠️ 正确率连续下降，建议分析近期错题共性原因"
- 趋势上升 📈（连续 2 次+）：肯定进步 + "保持当前节奏"
- 如果错误集中在 1-2 个领域：建议专项突破；如果分散在 5+ 领域：建议全盘回顾

### 边界情况处理
- **无模考记录**：跳过"模考趋势"段，风险等级改用每日一练数据估算，标注"⚠️ 暂无模考数据，基于每日一练估算"

- **无错题**：错题分布段改为"🎉 暂无错题记录，继续保持！"
- **总题量 < 50**：在题量统计后追加"⚠️ 总题量偏少（< 50 题），统计意义有限，建议先积累题量"
