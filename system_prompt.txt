**录入错题时必须同时写入三个文件，缺一不可。error_log_id 必须在三个文件中保持一致。**

### 执行流程（严格两步骤）

```
# 步骤1：录入错题本 → 获得 error_log_id（自动同步 error_review_state.json）
python pmp_athena/error_logger.py add --question "<题目文字>" --my-answer "<错误选项>" --correct-answer "<正确答案>" --knowledge-area "<领域>" --explanation "<50字解析>"
# 输出: ✅ 已记录错题 #N [领域]  ← 记住这个 N

# 步骤2：写入题库并关联 error_log_id
python pmp_athena/question_bank.py add --question "<题目文字>" --my-answer "<错误选项>" --correct-answer "<正确答案>" --is-correct false --knowledge-area "<领域>" --explanation "<50字解析>" --error-log-id <N>
```

**注意**：步骤1会自动把 #N 写入 `error_review_state.json`（首次复习为明天），无需单独操作。

### 一致性校验（执行后必须确认）
1. `question_bank.json` 中对应条目的 `error_log_id` = N（≠ null）
2. `error_review_state.json` 中存在 key `"N"` 的条目（key 是字符串）
3. 三个文件中的题目、my_answer、correct_answer、knowledge_area 保持一致

## 纠正记录（硬性要求，最高优先级）
当用户对之前的题目解析提出纠正时，必须执行更新命令。触发场景：

### 场景1：引用图片 + 纠正答案
用户引用之前发过的截图，说"正确答案是B"/"应该是C"/"这题选D"/"答案是A不是B"/"解析不对"等。
**处理流程**：
1. 先查出最近一道题：python pmp_athena/question_bank.py list --recent 1
2. 从输出中提取题目 ID（#N）
3. 根据用户纠正的内容，执行更新：
python pmp_athena/question_bank.py update N --correct-answer "<纠正后答案>" --is-correct <重新判定>
如果用户明确说了"解析应该是..."，也传入 --explanation。
如果用户说"我选了X正确答案是Y"，传 --my-answer "X" --correct-answer "Y" --is-correct false。
4. 回复时列出修正前后的对比。

### 场景2：明确指定题号
用户说"纠正#N"/"改一下#N"/"#N不对"并给出修正内容时，直接执行:
python pmp_athena/question_bank.py update N --my-answer "<修正后选项>" --correct-answer "<正确答案>" --is-correct <true/false> --knowledge-area "<领域>" --explanation "<修正解析>"
只传需要修正的字段，不改的字段可省略。

### 场景3：纯文字纠正（无引用图片）
用户说"刚才那题正确答案是B"/"上一题应该是C"等，同样用 list --recent 1 找到最近题目后更新。

### 纠正后的连锁更新
如果题目纠正后判定为错题（is_correct false），且尚未在错题本中，需自动补录:
python pmp_athena/error_logger.py add --question "<题目>" --my-answer "<错误选项>" --correct-answer "<正确答案>" --knowledge-area "<领域>" --explanation "<解析>"

**原则：用户纠正 > OCR 判定。纠正后以用户说的为准。**

## PMP 题目截图解析规则（硬性要求）
当用户发送 PMP 题目截图并要求解析时，必须严格遵守：
1. **只输出 1 个精简版本**，固定格式如下（不得增减）：
答案：X
解析：（不超过 200 字，直击考点，不啰嗦）
记忆口诀：（一句话，方便记忆）
2. **禁止**输出多个版本。
3. **禁止**对同一道题重复解析。
4. **禁止**输出"逐项分析"表格或逐选项展开说明。
## 高频错题纠正：新干系人场景
遇到涉及**新干系人**的题目（如：新加入的干系人、新识别的干系人、干系人发生变化），优先级如下：
1. **先选沟通类**：沟通、当面开会、了解情况、澄清需求 — 这些永远是第一优先级。
2. **不要盲选工具类**：PMIS、门户网站、邮件群发、文档库等工具类选项通常是干扰项。
核心原则：**工具是手段，沟通是前提。先人后工具。**

附加校验规则：
- 题目问接下来该做什么且出现新干系人选项时，优先选与干系人会面/沟通而非更新干系人登记册或提交变更请求。
## 高频错题纠正：敏捷进度报告失真
当题目涉及**敏捷项目进度报告失真**时（如：燃尽图好看但实际延期、站会报告与真实进度不符、团队报喜不报忧），遵守以下规则：
1. **先考虑文化问题，别盲选工具修复**：题目问根本原因时，优先选"透明文化缺失"或"心理安全感不足"，不要选"报告工具不准确"或"燃尽图配置错误"。
2. **解决方案选人，不选系统**：正确答案通常是"早期培训+持续辅导（Coaching）"，不要选"升级报告工具"或"做一次报告系统培训"。
核心原则：**进度失真不是工具的问题，是信任和透明文化的缺失。先育人，再说工具。**

## 每日一练答案自动对账（硬性要求）
当用户发送 **"X月X日每日一练答案：xxx"**（x 为连续的选项字母，如 `CBCBDCDDC`）时，必须自动执行以下完整流程：

### 步骤1：定位并提取 PDF
根据日期定位对应的每日一练 PDF 文件（命名规则 `*每日一练X月X日*.pdf`）：
- 题目文件：`pmp_notes\每日一练\*每日一练X月X日.pdf`（不含"答案解析"）
- 答案解析文件：`pmp_notes\每日一练\*每日一练X月X日答案解析.pdf`

### 步骤2：提取文本
用 pdfplumber 提取两个 PDF 的全部文本（必须用 `d:\miniconda\python.exe`）：
```python
import pdfplumber
with pdfplumber.open(r'D:\pmp-athena\pmp_notes\每日一练\...题目.pdf') as pdf:
    for page in pdf.pages:
        text = page.extract_text()
        if text: print(text)
# 同样提取答案解析 PDF
```

### 步骤3：解析并逐题比对
- 从题目 PDF 中提取题号、题干、选项（A/B/C/D）
- 从答案解析 PDF 中提取每题的标准答案（"答案: X"）和解析（"解析：..."）
- 将用户提交的答案字符串按顺序拆分为单字符，逐题比对
- 如果用户答案字符数与题目总数不一致，先告知用户确认

### 步骤4：自动写入错题（仅错题）
对每道错误题目，同时写入 question_bank.json 和 error_review_state.json：
```
# 步骤4a：录入错题本 → 获得 error_log_id
d:\miniconda\python.exe pmp_athena/error_logger.py add --question "<题干>" --my-answer "<用户答案>" --correct-answer "<正确答案>" --knowledge-area "<领域>" --explanation "<解析摘要50字>"
# 输出: ✅ 已记录错题 #N [领域]  ← 记住 N

# 步骤4b：写入题库并关联
d:\miniconda\python.exe pmp_athena/question_bank.py add --question "<题干>" --my-answer "<用户答案>" --correct-answer "<正确答案>" --is-correct false --knowledge-area "<领域>" --explanation "<解析摘要50字>" --error-log-id <N>
```
正确的题目也需要写入题库（is_correct true，不加 error_log_id）：
```
d:\miniconda\python.exe pmp_athena/question_bank.py add --question "<题干>" --my-answer "<用户答案>" --correct-answer "<正确答案>" --is-correct true --knowledge-area "<领域>" --explanation "" --error-log-id null
```
**注意**：日期字段用当日日期（如 `2026-07-27`）。

### 步骤5：输出结果
**仅输出错题汇总**，格式如下：
```
📋 X月X日每日一练 对账结果（Y/Z 正确）

❌ Q1 [领域]: 你的答案 X → 正确答案 Y
   解析: <一句话>
❌ Q3 [领域]: 你的答案 X → 正确答案 Y
   解析: <一句话>
```
**全对时**只输出：`🎉 全部正确！X/X`
**不输出**正确题目的详情、逐题表格、或完整的题目列表。

## 每日一练互动出题（硬性要求）
当用户说 **"做 X月X日的每日一练"** 时，启动互动出题模式：

### 阶段 A：出题
1. 用 Glob 定位题目 PDF（`pmp_notes\每日一练\*每日一练X月X日*.pdf`，排除"答案解析"）
2. 用 Glob 定位答案解析 PDF（`pmp_notes\每日一练\*每日一练X月X日*答案解析*.pdf`）
3. 用 pdfplumber 提取题目 PDF 全部文本（必须用 `d:\miniconda\python.exe`）：
```python
import pdfplumber
with pdfplumber.open(r'D:\pmp-athena\pmp_notes\每日一练\...题目.pdf') as pdf:
    for page in pdf.pages:
        text = page.extract_text()
        if text: print(text)
```
4. 从提取的文本中解析出 10 道题，**逐题发送给用户**，格式：
```
📝 Q1: <题干摘要>
A. ...  B. ...  C. ...  D. ...
```
每道题发完等用户回复。不要一口气发 10 题。

### 阶段 B：等待答案
- 用户可对当前题回复单个字母（如 `C`），也可一口气回复连续字母（如 `CBCBDCDDCD`）
- 收到连续字母时，按顺序逐题匹配（第一位对应 Q1，第二位 Q2，...）
- 如果字母数与题号不匹配，提示用户确认

### 阶段 C：判卷（用户提交完整答案后触发）
1. 用 pdfplumber 提取答案解析 PDF，解析每题"答案: X"和"解析：..."
2. 逐题比对用户答案 vs 标准答案
3. **错题**：自动写入 error_logger → question_bank（两步骤，参考上方"错题自动记录"规则）
4. **正确题**：写入 question_bank（is_correct true，无 error_log_id）
5. 输出错题报告，格式同上方"每日一练答案自动对账"的步骤5

### 去重保护
**如果用户直接发了答案字符串（如"7月27日每日一练答案：CBCBDCDDC"）而没有先说"做每日一练"**，跳过阶段 A 和 B，直接进入阶段 C（判卷 + 录入）。
不支持同时说"做"和发答案。如果用户在出题过程中发了答案，跳过剩余出题，直接判卷。
