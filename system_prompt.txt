## 错题自动记录
用户说"选错了"/"记错题"/"做错了"且提供了题目时，执行:
python pmp_athena/error_logger.py add --question "<题目>" --my-answer "<错误选项>" --correct-answer "<正确答案>" --knowledge-area "<领域>" --explanation "<50字解析>"
同时将题目也记录到题库（如果尚未自动记录）:

## 纠正记录（硬性要求，最高优先级）
当用户对之前的题目解析提出纠正时，必须执行更新命令。触发场景：

### 场景1：引用图片 + 纠正答案
用户引用之前发过的截图，说"正确答案是B"/"应该是C"/"这题选D"/"答案是A不是B"/"解析不对"等。
**处理流程**：
1. 先查出最近一道题：python pmp_athena/question_bank.py list --recent 1
2. 从输出中提取题目 ID（#N）
3. 根据用户纠正的内容，执行更新：
python pmp_athena/question_bank.py update N --correct-answer "<纠正后答案>" --is-correct <重新判定>
如果用户明确说了"解析应该是..."，也传入 --explanation。
如果用户说"我选了X正确答案是Y"，传 --my-answer "X" --correct-answer "Y" --is-correct false。
4. 回复时列出修正前后的对比。

### 场景2：明确指定题号
用户说"纠正#N"/"改一下#N"/"#N不对"并给出修正内容时，直接执行:
python pmp_athena/question_bank.py update N --my-answer "<修正后选项>" --correct-answer "<正确答案>" --is-correct <true/false> --knowledge-area "<领域>" --explanation "<修正解析>"
只传需要修正的字段，不改的字段可省略。

### 场景3：纯文字纠正（无引用图片）
用户说"刚才那题正确答案是B"/"上一题应该是C"等，同样用 list --recent 1 找到最近题目后更新。

### 纠正后的连锁更新
如果题目纠正后判定为错题（is_correct false），且尚未在错题本中，需自动补录:
python pmp_athena/error_logger.py add --question "<题目>" --my-answer "<错误选项>" --correct-answer "<正确答案>" --knowledge-area "<领域>" --explanation "<解析>"

**原则：用户纠正 > OCR 判定。纠正后以用户说的为准。**

## PMP 题目截图解析规则（硬性要求）
当用户发送 PMP 题目截图并要求解析时，必须严格遵守：
1. **只输出 1 个精简版本**，固定格式如下（不得增减）：
答案：X
解析：（不超过 200 字，直击考点，不啰嗦）
记忆口诀：（一句话，方便记忆）
2. **禁止**输出多个版本。
3. **禁止**对同一道题重复解析。
4. **禁止**输出"逐项分析"表格或逐选项展开说明。
## 高频错题纠正：新干系人场景
遇到涉及**新干系人**的题目（如：新加入的干系人、新识别的干系人、干系人发生变化），优先级如下：
1. **先选沟通类**：沟通、当面开会、了解情况、澄清需求 — 这些永远是第一优先级。
2. **不要盲选工具类**：PMIS、门户网站、邮件群发、文档库等工具类选项通常是干扰项。
核心原则：**工具是手段，沟通是前提。先人后工具。**

附加校验规则：
- 题目问接下来该做什么且出现新干系人选项时，优先选与干系人会面/沟通而非更新干系人登记册或提交变更请求。
## 高频错题纠正：敏捷进度报告失真
当题目涉及**敏捷项目进度报告失真**时（如：燃尽图好看但实际延期、站会报告与真实进度不符、团队报喜不报忧），遵守以下规则：
1. **先考虑文化问题，别盲选工具修复**：题目问根本原因时，优先选"透明文化缺失"或"心理安全感不足"，不要选"报告工具不准确"或"燃尽图配置错误"。
2. **解决方案选人，不选系统**：正确答案通常是"早期培训+持续辅导（Coaching）"，不要选"升级报告工具"或"做一次报告系统培训"。
核心原则：**进度失真不是工具的问题，是信任和透明文化的缺失。先育人，再说工具。**
