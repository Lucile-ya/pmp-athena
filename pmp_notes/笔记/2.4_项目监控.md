# 2.4 项目监控

## 监控过程组概览

监控过程组**跟踪、审查和调整**项目进展与绩效，识别偏差并采取纠正措施。

| 监控过程 | 所属领域 | 核心关注 |
|----------|----------|----------|
| 4.5 监控项目工作 | 整合管理 | 全面跟踪、生成工作绩效报告 |
| 4.6 实施整体变更控制 | 整合管理 | CCB 审批变更、更新基准 |
| 5.5 确认范围 | 范围管理 | 干系人正式验收可交付成果 |
| 5.6 控制范围 | 范围管理 | 防止范围蔓延 |
| 6.6 控制进度 | 进度管理 | 跟踪进度偏差、预测 |
| 7.4 控制成本 | 成本管理 | 挣值分析、成本预测 |
| 8.3 控制质量 | 质量管理 | 检查可交付物是否符合标准 |
| 9.6 控制资源 | 资源管理 | 监控资源使用、解决问题 |
| 10.3 监督沟通 | 沟通管理 | 沟通是否有效 |
| 11.7 监督风险 | 风险管理 | 风险审计、储备分析 |
| 12.3 控制采购 | 采购管理 | 合同管理、索赔处理 |
| 13.4 监督干系人参与 | 干系人管理 | 干系人参与度变化 |

## 核心监控工具

| 工具 | 用途 | 所属过程 |
|------|------|----------|
| 挣值分析 (EVM) | 综合衡量成本与进度绩效 | 控制成本/进度 |
| 偏差分析 | 对比实际与基准的差距 | 控制范围/进度/成本 |
| 趋势分析 | 预测未来绩效 | 控制进度/成本 |
| 变更控制工具 | 管理变更请求全流程 | 整体变更控制 |
| 检查 | 确定可交付物是否达标 | 控制质量/确认范围 |
| 风险审计 | 审查风险管理过程有效性 | 监督风险 |
| 储备分析 | 检查剩余应急储备是否充足 | 监督风险 |

## 整体变更控制流程 (4.6)

```
变更请求提交
    ↓
评估变更对范围/进度/成本/质量的影响
    ↓
提交 CCB (变更控制委员会) 审批
    ↓
├─ 批准 → 更新项目管理计划/基准 → 通知干系人 → 实施
└─ 拒绝 → 记录原因 → 通知提出人
```

## 变更控制关键考点

| 原则 | 说明 |
|------|------|
| 任何变更都需正式书面请求 | 口头请求需补充书面记录 |
| CCB 审批通过前不得实施 | 项目经理不能自行批准影响基准的变更 |
| 影响基准的变更需走正式流程 | 紧急变更也需事后补完整流程 |
| 项目经理审批不涉及基准的变更 | 但要确保所有变更都经过评估 |
