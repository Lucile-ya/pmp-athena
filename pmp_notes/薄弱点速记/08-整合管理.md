# 🟢 整合管理 · 可背诵版

---

## 一、概念

**识别、定义、组合、统一和协调**各项目管理过程——PM 是**整合者**。

---

## 二、七大过程

| 过程 | 过程组 | 核心输出 |
|------|--------|----------|
| 4.1 制定项目章程 | 启动 | **项目章程**、假设日志 |
| 4.2 制定项目管理计划 | 规划 | 项目管理计划 |
| 4.3 指导与管理项目工作 | 执行 | 可交付成果、变更请求 |
| 4.4 管理项目知识 | 执行 | 经验教训登记册 |
| 4.5 监控项目工作 | 监控 | 工作绩效报告 |
| 4.6 **实施整体变更控制** | 监控 | 批准的变更请求 |
| 4.7 结束项目或阶段 | 收尾 | 最终报告、经验教训 |

## 三、项目章程

| 属性 | 内容 |
|------|------|
| 签发人 | **发起人 (Sponsor)** |
| PM 角色 | 参与制定，**不签发** |
| 作用 | **正式授权** PM 动用资源 |
| 内容 | 目的、目标、成功标准、里程碑、预算、PM 任命 |

**口诀**：**章程发起人签，授权 PM 干**

---

## 四、整体变更控制（最高频）

```
变更请求提交
  ↓
评估对范围/进度/成本/质量的影响  ← 第一步！
  ↓
提交 CCB 审批
  ↓
批准后更新基准 + 实施
  ↓
记录变更日志
```

### 关键规则

| 规则 | 说明 |
|------|------|
| 任何变更需**书面**请求 | 口头需补书面 |
| **CCB 批准前不得实施** | 先评估再执行 |
| PM **不能**自行批准影响基准的变更 | 可批准不涉及基准的小变更 |
| 口头变更 ≠ 已批准 | 必须走流程 |

**口诀**：**记录→评估→CCB→批准→实施**

## 六、高频考点

1. 变更流程：评估 → CCB → 批准 → 实施
2. 章程签发人 = 发起人
3. 经验教训**全周期**记录，收尾总结
4. 问题日志 vs 风险登记册（已发生 vs 可能发生）
5. PM 是整合者，统管各知识领域变更

## 七、易错陷阱

| ❌ 错 | ✅ 对 |
|------|------|
| 收到变更立刻执行 | 先评估 + CCB |
| PM 批准基准变更 | CCB 批准 |
| 口头接受范围变更 | 书面 CR |
| 跳过评估直接提交 CCB | 先分析影响 |
| 已发生问题写风险登记册 | 问题日志 |

## 八、做题决策链

```
新变更/范围增加/客户加功能？
  → 记录 CR → 评估影响 → CCB → 批准后实施
问章程？
  → 发起人签发，正式授权 PM
问 PM 第一步？
  → 分析/记录/评估（P1），不是执行
Risk vs Issue？
  → 已发生=Issue，可能发生=Risk
```
