## 一、概念

**商业环境** = 确保项目**对齐组织战略**，持续**创造并兑现商业价值**。

| 维度 | 含义 |
|------|------|
| 战略对齐 | 项目必须服务组织战略目标 |
| 价值论证 | 回答「为什么要做」 |
| 利益实现 | 收益何时、如何衡量 |
| 外部环境 | 法规/市场/技术/经济变化 |
| 组织变革 | 项目改变工作方式，要管抵制 |

**PM 边界**：商业论证、效益计划由**发起人/商业分析师**主导；PM **只能建议，不能擅自改**。

## 二、过程链

| 过程 | 时机 | 输出 | 工具 |
|------|------|------|------|
| B.1 开发商业论证 | 启动前 | 商业论证、利益管理计划 | ROI/NPV/IRR |

**过程口诀**：**论证在前，变革在启，利益跟全程**

---

## 三、两大商业文件

### 商业论证 (Business Case) — 为什么做？

四要素：**需分推评**
1. **需** — 商业需求
2. **分** — 形势分析
3. **推** — 推荐方案
4. **评** — 成本效益（财务+非财务）

### 效益管理计划 — 值多少、何时见？

- KPI、ROI、NPV、IRR、回收期
- 收益可能在**项目结束后**才兑现
- **效益 ≠ 可交付物**

---

## 四、财务指标

| 指标 | 判断 |
|------|------|
| NPV | **> 0** 才有价值 |
| ROI | 收益/投资 |
| IRR | 与基准收益率比较 |

**口诀**：**NPV 大于零才值得投**

---

## 五、变革管理 · ADKAR

| 字母 | 含义 |
|------|------|
| A | Awareness 认知 |
| D | Desire 意愿 |
| K | Knowledge 知识 |
| A | Ability 能力 |
| R | Reinforcement 巩固 |

**口诀**：**认意愿知能固**

变革四步：识别干系人 → 沟通好处 → 培训支持 → 管理抵制

## 六、合规 & 环境

### EEF vs OPA
- **EEF**：管不了（法规、文化、市场）
- **OPA**：拿来用（模板、经验教训）

**口诀**：**EEF 管不了，OPA 拿来用**

### 合规
- 内部 = 组织政策；外部 = 法律法规
- **合规是底线，价值是目标**

### 外变处理
**先评估影响 → 再决定是否变更**

---

## 七、高频考点

1. 商业论证谁写、PM 能不能改
2. 效益 vs 可交付成果
3. 变革抵制 → ADKAR + 沟通，别强制
4. 项目组合 = 战略优先级排序
5. 三重底线：经济 + 社会 + 环境

## 八、易错陷阱

| ❌ 错 | ✅ 对 |
|------|------|
| 商业论证一次性 | 持续审查 |
| PM 改商业论证 | 只能建议 |
| 合规达标 = 成功 | 还要看战略和效益 |
| 法规变了立刻改计划 | 先评估影响 |

| CEO 想上新技术就立刻立项 | 第一步先做商业论证 |

| （模拟考试1）合规规划一次就完事 | **审计持续监控**合规 |
| （模拟考试1）多团队敏捷强制统一模板 | **协商一致**的交付实践，别一刀切 |

## 九、做题决策链

```
题干有 战略/价值/法规/变革/效益/NPV？
  ├─ 为什么做 / CEO 想上新技术 → 商业论证（需分推评）
  ├─ 选哪个项目 → 战略对齐 + 效益 + 可测量（别 CEO 拍板）
  ├─ 效益怎么量 → 效益管理计划 / KPI
  ├─ 抵制变革 → ADKAR + 沟通培训（不强制）
  ├─ 法规/市场/外来投资变了 → 先评估对目标/合规/战略影响
  ├─ 执行中新组织流程 → 先评估收益 vs 风险，再决定是否整合
  └─ NPV/ROI → NPV>0 才有价值

合规题？
  ├─ 规划一次就完？ → 否，审计持续监控
  ├─ 未授权功能（哪怕发起人喜欢）→ 立刻停工 + 正式变更
  └─ 合规缺陷 vs 赶发布 → 发布前必须纠正

多团队敏捷强制统一模板？ → 协商一致的交付实践，别一刀切
无历史经验的技术故障？ → 先内部技术分析，别一上来外聘
PM 权 > 职能经理？ → 强矩阵（不是纯项目型）
问 First → 分析/评估/沟通，不选终局方案或升级
```
