## 先搞懂（26 题）

进度题核心就一件事：**关键路径上没有可以浪费的空闲。** 非关键路径有浮动，晚一点不一定拖总工期。


### 自动钉死（更新于 2026-11-17）

> 来自错题本高频口诀，跟「易错陷阱 / 背这句」同源，每天先扫这 5 条。

1. **估算偏大用WBS自下而上重估** — 别拍脑袋砍数字
2. **SV=EV-PV报告进度偏差** — 别用完工百分比冒充SV
3. **敏捷估算用相对估算故事点** — 别每日站会追绝对工期
4. **进度异常先分析再行动** — 别先全面赶工
5. **敏捷用交付价值证明进展** — 别靠发起人口头说正常

### 赶工 vs 快速跟进

赶工 = 同一件事加人/加班，**花钱**，顺序不变，风险主要是累和贵。  
快速跟进 = 本来先后做的事搭着做，**顺序变了**，返工风险上升。  
题干强调「必须压缩而且预算紧」才考虑并行；没说钱的约束就不要默认选快速跟进。

### 进度落后时不要直接全员加班

先问为什么落后（资源被抽走、依赖、范围暗增）。原因没找到就加班，是跳步骤。SPI < 1 只告诉你落后，不告诉你该赶工还是该改依赖。

公式和网络图规则在下面，先建立「关键路径零浮动、压缩要分清加钱还是搭接」。

## 三、关键路径 CPM

| 概念 | 定义 |
|------|------|
| **关键路径** | 最长路径 = 项目**最短**完成时间 |
| **总浮动时间** | 活动可推迟不影响总工期 |
| **关键路径活动** | 总浮动时间 = **0** |
| 多条关键路径 | ✅ 可能同时存在 |

**口诀**：**最长路 = 最短工期，浮动为零在关键**

---

## 四、进度压缩（必考）

| 技术 | 原理 | 副作用 | 适用 |
|------|------|--------|------|
| **赶工 Crashing** | **加资源** | **增加成本** | 资源驱动型活动 |
| **快速跟进 Fast Tracking** | **并行**活动 | **增加风险**、可能返工 | 有依赖时可并行 |

**选择口诀**：
- 有钱没时间 → **赶工**
- 敢担风险 → **快速跟进**
- 默认优先 → **赶工**（PMP 常考）

## 六、与挣值联动

- **SV = EV − PV**，**SPI = EV / PV**
- SPI < 1 → 进度落后
- 进度落后 + 要压缩 → 先分析根因，再选赶工/快速跟进

3. 进度落后怎么压缩
4. 关键路径延迟 = 项目延迟
5. 先优化资源再调进度

## 八、易错陷阱

| ❌ 错 | ✅ 对 |
|------|------|
| 快速跟进不加风险 | 并行增加风险 |
| 只有一条关键路径 | 可能多条 |
| 缩短非关键活动能缩总工期 | 只有关键路径才行 |
| 进度问题直接加班 | 先根因分析 |
| 要提前完工且不能加成本 | **快速跟进**（并行）；赶工要加钱 |
| 进度落后却在写文档 | 审查精简工件，抓实际交付 |
| 粗估偏大就拍脑袋砍 | 用 **WBS 自下而上**重估 |
| 问进度偏差却报完工% | **SV = EV − PV** |
| 发起人要砍两个月就承诺 | 先做**赶工/快速跟进权衡分析** |
| 浮动内延误被私下传成落后 | 用**结构化沟通**澄清真实状态 |
| 敏捷站会追绝对工期 | 用**相对估算**；价值证明进展 |
| 争议干系人开放乱辩 | **名义小组技术**结构化决策 |

## 九、做题决策链

```
问压缩工期？
  ├─ 发起人要砍工期就承诺？ → 先做赶工/快速跟进权衡分析
  ├─ 不能加成本 → 快速跟进（并行，风险↑）
  ├─ 可加资源/加钱 → 赶工
  ├─ 无可重叠活动 → 资源优化 / 赶工（别硬并行）
  └─ 先确认是否在关键路径上（非关键缩短无效）

问浮动时间 → 关键路径 TF = 0
给网络图 → 找最长路径 = 最短工期
问进度偏差怎么报 → SV = EV − PV（别用完工%）
估算偏大要修订 → WBS 自下而上重估（别拍脑袋砍）
进度异常 / SPI<1 → 先根因分析，再选压缩手段
浮动内延误被传成落后 → 结构化沟通澄清真实状态
敏捷站会追绝对工期 → 相对估算/故事点；用交付价值证明进展

争议干系人开放乱辩 → 名义小组技术结构化决策
进度落后但在写文件 → 砍不必要工件，抓交付
```
