# 先搞懂再做题（考前攻错）

> 不是背句子。每道题先在脑子里走完「发生了什么 → 现在该哪一步」，再看选项。  
> 你将近四成错题，不是概念没见过，是**跳步骤**：把后面正确的事，当成了现在该做的事。

---

## 一、PMP 把项目当成一条流水线

选项里经常 **好几条都对**。区别只在：现在走到哪一格。

```
搞清楚状况（分析/沟通/评估）
        ↓
走该走的流程（变更、合同、Backlog）
        ↓
动手（实施、换供应商、加功能）
        ↓
收尾（经验教训、释放资源、关项目）
```

题干问 **首先 / First** → 停在最上面那一格。  
题干问 **下一步 / Next** → 看已经做完哪一格，只往下走一格。  
题干问 **最好 / Best** → 可以选完整路径里最合适的，但仍不能越权、不能镀金。

你容易把「最后也该做的好事」当成「现在就该做」。  
经验教训、加质量检查、换更好的供应商，本身没错，**时机错了就是错。**

## 二、用你自己的三道题把流水线走通

### #83　数据已经丢了，你选了「开经验教训会」

**发生了什么**  
部署漏了一步，用户电脑数据已经丢失。这不是「以后可能丢」，是**已经发生的问题**。

**你当时为什么会选 C**  
C 是让成员把案例当经验教训来审查。听起来很 PMI：重视复盘、全员参与。  
但经验教训是**后面**的格子——根因还没找到，现在开会等于跳过治疗直接写病历。

**正确思路**  
1. 已经发生 → 当 **问题** 处理，不是风险。  
2. 问「首先」→ 先搞清楚**为什么会丢**（跟团队找根因）。  
3. 找到原因、稳住部署之后，再记经验教训，防止再发。

A 就是「跟团队讨论根本原因，同时盯着部署」。所以选 A。

**下次怎么认**  
看到「已经丢失 / 已经失败 / 已经冲突」+「首先」→ 先根因或先沟通，**不要先选经验教训、不要先选换顾问、不要先选上报。**

---

### #84　东西做完了还有余钱，你选了「拿去加质量检查」

**发生了什么**  
商定的产品要求已经满足，项目要结束。还剩时间和超额预算。有人想继续加功能。

**你当时为什么会选 B**  
B 是用剩余资源做额外质量检查。听起来负责：不浪费、还提升质量。  
但项目成功标准是「满足已商定的要求」，不是「把钱花光」或「主动再镀一层金」。

**正确思路**  
PMP 的范围原则是：**做且只做该做的**。  
- 加功能 = 镀金（Gold Plating），即使免费也不做。  
- 加一轮没要求的 QC，同样是范围外的工作。  
- 余下的时间和钱属于组织，确认关闭标准后**释放**，交给别的项目。

所以选 C：确认已满足关闭标准，释放剩余预算和资源。

**下次怎么认**  
「已满足要求 / 即将结束 / 还有剩余时间或预算 / 有人想加东西」→ 收摊，不加戏。  
只有**变更被批准**才能加；拥护者口头想要 ≠ 已批准。

### #87　供应商说交不了货，你选了「改产品待办」

**发生了什么**  
迭代交付的生产线，供应商告知设备无法按约定日期到达。问**下一步**。

**你当时为什么会选 C**  
C 是更新产品待办事项来消化延期。敏捷题里「有变化就改 Backlog」出现太多次，手会自动往那边走。  
但这件事的对象是**合同里的卖方**，不是 PO 和故事点。Backlog 解决不了「货还在不在路上」。

**正确思路**  
1. 已经有采购协议 → 权利和补救办法写在合同里。  
2. 「下一步」= 先看协议允许你做什么（罚款、换货、延期条款），再决定换商或改迭代。  
3. 先改 Backlog、先找新供应商、先重排剩余迭代，都是后面的格子。

所以选 A：审查采购协议。

**下次怎么认**  
出现「供应商 / 卖方 / 合同 / 采购」+ 交不了、质量差、要改 SOW → **先翻协议**，不要先当内部敏捷问题处理。

## 三、六条优先级，其实是同一句话

**没看清状况，就不要动手；能商量，就不要告状；有流程，就不要口头改。**

| 代号 | 人话 | 你什么时候会用错 |
|------|------|------------------|
| P1 先分析 | 先评估、先查计划、先找根因 | 选项里有「立即执行」特别香 |
| P2 先协作 | 面对面、跟职能经理谈 | 选项里有「找发起人」看起来痛快 |
| P3 先流程 | 变更要 CR/CCB；敏捷要进 Backlog | 「客户已经开口了」你就想答应 |
| P4 先根因 | 重复缺陷、已发生问题 | 你想先补丁、先开教训会 |
| P5 先预防 | 问「避免再发」 | 你选加强检查（那是事后） |
| P6 团队来 | 怎么估、怎么干，团队定 | 你选 PM 或 SM 替他们做决定 |

做题时从上往下砍选项。能同时说得通时，**更靠前的那条赢**。

## 四、几个必须想通的对照（不是背单词）

### 问题 vs 风险

- **风险** = 还没发生，有概率。进风险登记册，选应对策略。  
- **问题** = 已经砸在地上。进问题日志，先处理、先找根因。  

同一件事，时态一变，答案就变。组件「可能延迟 45 天」是风险；「已经 45 天拿不到」是问题。

### 变更 vs 镀金

- 别人提出来、可能影响基准 → **变更请求**，评估后再说。  
- 你或团队「顺便做更好」→ **镀金**，直接拒绝。  
- 项目已经达到关闭标准 → 余钱不是奖金，是要还回去的。

### 预测型 vs 敏捷：谁说了算

| 事情 | 预测型 | 敏捷 |
|------|--------|------|
| 范围变了 | CR → CCB | PO 写入 Backlog，当前 Sprint 默认不加 |
| 谁定优先级 | 计划 + 发起人/CCB | **PO**（不是 SM，不是 PM） |
| 谁决定怎么做 | PM 整合，团队执行 | **开发团队**自组织 |
| 谁清障碍 | PM | **SM**（你把障碍丢给 PO 就会错） |

混合题：看**这句话卡在哪一段**。硬件规格很清楚 → 那段用预测；软件还在变 → 那段用敏捷。不要整题只套一种。

### 为什么冲突默认「合作」

PMP 认为长期项目靠关系。强迫能结束争吵，但留下怨气，后面还要一起干活。  
所以：没写「着火了 / 必须立刻决策 / 沟通已经无效」，就选合作、面对面。  
矩阵组织抢人同理：人的老板是**职能经理**，你没有指挥权，先协商；协商不动再升级。

### 为什么新干系人要先见面

登记册、PMIS 是工具。你还不清楚他要什么、怕什么，填表是在瞎填。  
「先人后工具」= 先获得信息，再更新文件。不是永远不更新文件。

### 为什么 QA / QC 总搞反

把它们想成医院，不要想成缩写：

- **QC 控制质量** = 化验这杯血合格不合格（查**这一件产品**）。  
- **QA 管理质量** = 化验室流程乱不乱、要不要改流程（查**过程**）。  
- **确认范围** = 家属在报告上签字验收。必须化验合格之后才能签。

题干出现「检测出 errors / 可交付物不合格」→ QC。  
出现「审计、没按质量计划做、改进过程」→ QA。

### 为什么数字题必须先想 EV

PV 是计划承诺，AC 是实际花出去的钱，**EV 是「按预算计价，你真正干完了多少」**。  
只看「已经花了 80%」不知道是超支还是正常——也许只干完 50%。  
所以先问：工作完成了多少（EV），再跟 AC 比成本、跟 PV 比进度。

应急储备：已知风险，进成本基准，PM 能用。  
管理储备：未知未知，不在基准里，要用等于改基准，得走变更。
