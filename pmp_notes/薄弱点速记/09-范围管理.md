# 🟢 范围管理 · 可背诵版

> **你的数据**：错题本 **28** 题  
> **总口诀**：**范围基准三件套，先 QC 后确认**

---

## 一、概念

确保项目**做且只做**该做的事 — 定义和控制什么在内、什么在外。

---

## 二、六大过程

| 过程 | 过程组 | 核心输出 |
|------|--------|----------|
| 5.1 规划范围管理 | 规划 | 范围管理计划 |
| 5.2 收集需求 | 规划 | 需求文件、需求跟踪矩阵 |
| 5.3 定义范围 | 规划 | 项目范围说明书 |
| 5.4 创建 WBS | 规划 | WBS、**范围基准** |
| 5.5 **确认范围** | 监控 | 验收的可交付成果 |
| 5.6 **控制范围** | 监控 | 变更请求 |

---

## 三、范围基准

**范围基准 = WBS + WBS 词典 + 范围说明书**

| 概念 | 说明 |
|------|------|
| WBS | 可交付成果逐层分解为**工作包** |
| 工作包 | 最底层，可估算成本和时间 |
| 100% 规则 | WBS 涵盖项目 **100%** 工作 |
| 控制账户 | 管理控制点 |

**口诀**：**基准三件套：WBS + 词典 + 说明书**

---

## 四、需求 vs WBS

| | 需求 | WBS |
|--|------|-----|
| 回答 | 客户要什么 | 怎么做/怎么分解 |
| 工具 | 访谈、原型、焦点小组 | 分解 |

**口诀**：**需求是 WHAT，WBS 是 HOW 分解**

---

## 五、确认范围 vs 控制质量

| | 控制质量 QC | 确认范围 |
|--|-------------|----------|
| 做什么 | 检查是否**合格** | 干系人**正式验收** |
| 顺序 | **先** | **后** |

**口诀**：**先 QC 后确认**

---

## 六、范围蔓延 & 镀金

| 概念 | 说明 | 态度 |
|------|------|------|
| **范围蔓延** | 未控制的范围增加 | ❌ 禁止 |
| **镀金** Gold Plating | 主动加未要求的功能 | ❌ 不提倡 |
| 正确做法 | 记录 CR → 评估 → CCB 批准 | ✅ |

**口诀**：**加功能走变更，拒绝镀金蔓延**

---

## 七、高频考点

1. 范围基准三组件
2. WBS 100% 规则
3. 确认范围 vs 控制质量顺序
4. 客户加功能 → CR，不能口头接受
5. 需求跟踪矩阵的作用

---

## 八、易错陷阱

| ❌ 错 | ✅ 对 |
|------|------|
| 需求 = WBS | 需求是输入，WBS 是分解 |
| 先确认范围再 QC | 先 QC 后确认 |
| 口头接受范围变更 | 走 CR + CCB |
| PM 主动加功能（镀金） | 不提倡 |
| WBS 包含不属于项目的工作 | 100% 规则 |

---

## 九、做题决策链

```
客户要加功能？
  → 记录 CR → 评估 → CCB（不是口头接受）
问范围基准？
  → WBS + 词典 + 说明书
验收/Sign-off？
  → 确认范围（QC 之后）
WBS 分解？
  → 100% 规则，分解到工作包
```
