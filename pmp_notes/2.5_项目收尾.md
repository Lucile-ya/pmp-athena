# 2.5 项目收尾

## 结束项目或阶段 (4.7)

正式完成或关闭项目、阶段或合同的过程。

| 类别 | 活动 |
|------|------|
| 交付 | 获得干系人对最终可交付成果的**正式验收** |
| 移交 | 将成果移交给运营或客户 |
| 归档 | 归档项目文档、合同记录 |
| 总结 | 完成经验教训总结、存档到组织知识库 |
| 释放 | 释放项目资源（人员、设备、资金） |
| 庆祝 | 认可团队成就（可选但推荐） |

## 收尾检查清单

| # | 检查项 |
|----|------|
| 1 | 所有可交付成果是否已获得正式验收？ |
| 2 | 所有合同/采购是否已关闭？ |
| 3 | 经验教训是否已记录并移交？ |
| 4 | 项目文档是否已归档？ |
| 5 | 财务账目是否已结算关闭？ |
| 6 | 项目资源是否已释放？ |
| 7 | 最终报告是否已完成并分发？ |
| 8 | 是否已通知所有干系人项目结束？ |

## 合同收尾 vs 行政收尾

| | 合同收尾 | 行政收尾 |
|------|----------|----------|
| 对象 | 每次采购/合同 | 每个项目/阶段 |
| 活动 | 正式验收交付、结算、更新记录 | 归档、总结、释放资源 |
| 顺序 | 在行政收尾之前 | 收尾阶段的最后一步 |
| 关键输出 | 合同关闭通知 | 最终报告 |

## 收尾常见考点

| 场景 | 正确做法 |
|------|----------|
| 项目提前终止 | 仍需走正式收尾流程，记录已完成工作和经验教训 |
| 合同提前终止 | 按合同终止条款处理，走合同收尾 |
| 客户不签署验收单 | 继续沟通，说明正式验收的必要性 |
| 团队即将解散 | 确保经验教训已完成，给予认可和反馈 |
| 关键资源被调走 | 优先完成交接和文档归档 |
