# 2.3 项目执行

## 执行过程组概览

执行过程组按照项目管理计划来**完成工作**并满足项目要求。

| 执行过程 | 所属领域 | 核心活动 |
|----------|----------|----------|
| 4.3 指导与管理项目工作 | 整合管理 | 执行计划、产出可交付成果、提交变更请求 |
| 4.4 管理项目知识 | 整合管理 | 运用现有知识、创造新知识、记录经验教训 |
| 8.2 管理质量 (QA) | 质量管理 | 质量审计、过程改进 |
| 9.3 获取资源 | 资源管理 | 谈判、获得团队和实物资源 |
| 9.4 建设团队 | 资源管理 | 培训、团建、认可奖励 |
| 9.5 管理团队 | 资源管理 | 冲突管理、绩效反馈 |
| 10.2 管理沟通 | 沟通管理 | 按沟通计划发送信息 |
| 11.6 实施风险应对 | 风险管理 | 执行已批准的风险应对计划 |
| 12.2 实施采购 | 采购管理 | 招标、评标、签合同 |
| 13.3 管理干系人参与 | 干系人管理 | 与干系人沟通、处理问题 |

## 核心执行活动

### 4.3 指导与管理项目工作

| 输入 | 工具与技术 | 输出 |
|------|-----------|------|
| 项目管理计划 | 专家判断 | **可交付成果** |
| 批准的变更请求 | PMIS (项目信息系统) | 工作绩效数据 |
| EEF / OPA | 会议 | 变更请求、更新计划 |

### 4.4 管理项目知识

| 知识类型 | 说明 | 工具 |
|----------|------|------|
| 显性知识 | 可编写、可存储的知识 | 文档、数据库、经验教训登记册 |
| 隐性知识 | 个人经验、信念、洞察 | 人际交往、工作跟随、讨论会 |

### 执行期间关键决策点

| 场景 | 正确做法 |
|------|----------|
| 需要变更 | 提交变更请求 → 走整体变更控制 |
| 发现风险 | 记录 → 分析 → 规划应对 |
| 团队冲突 | 合作/解决问题（优先选择） |
| 新干系人 | 先见面沟通 → 更新登记册 |
| 卖方交付 | 检查验收 → 按合同付款 |
