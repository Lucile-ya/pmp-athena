# PMP17 项目的执行交付与收尾

> 来源：骐迹教育第 17 讲（PPTX · 第八版）。本讲核心是 **项目工作绩效域 + 交付绩效域**（变更/采购/知识/需求范围/质量成本）。收尾考点与「做完就关、别镀金」一并记在整合速记。

## 一、两域一句话

| 绩效域 | 干什么 | 考场信号 |
|--------|--------|----------|
| **项目工作** | 建过程、盯资源、采购、变更、学习 | 流程瓶颈、实物物流、招标、新工作进 backlog |
| **交付** | 需求→范围→可交付物→质量/价值落地 | WBS/DoD、需求演变、完成漂移、COQ |

**口诀：工作保运转，交付出成果；变更分适应/预测，知识分显性/隐性。**

## 二、项目工作绩效域（预期成果）

1. 有效率且有效果的绩效  
2. 适合项目与环境的过程（裁剪）  
3. 干系人适当沟通与参与  
4. 实物资源管得住  
5. 采购管得好  
6. 持续学习提升能力  

日常动作：管现有/新工作/变更 → 团队专注 → 系统流程 → 沟通 → 物流 → 采购协作 → 监督变更 → 知识转移。

### 过程优化三板斧

| 方法 | 用途 |
|------|------|
| 精益 / 价值流图 | 找浪费、提高增值比 |
| 回顾 / 经验教训 | 改过程，不是只吐槽人 |
| 资金优先级 | 「下一笔钱花哪」→ 最大化价值交付 |

审查过程一致性要够用，别把时间全耗在合规追踪而交不出成果。

### 制约因素要持续平衡

固定日期 / 法规 / 预算 / 质量政策 / 三重底线会变。  
新需求可能拉进度加预算；砍预算可能缩范围或松质量。  
职权内自权衡；超权找客户 / 发起人 / PO 谈备选与含义。

### 团队专注

平衡 **生产（交价值）** 与 **保护产能（团队健康）**；盯短长期进度、潜在延期与超支。

### 沟通

口头/书面、正式/非正式。特别请求暴增 → 沟通规划不足 → 回去补干系人信息需求。

### 实物资源目标

少搬运储存 · 消等待 · 减报废 · 保安全；物流并进主进度计划。

## 三、采购（高频）

- PM 通常 **无签约权**，与合同官/法务协作。  
- 招标前：IFB/RFP/RFQ、SOW、条款；**投标人会议**统一理解。  

| 文件 | 何时用 |
|------|--------|
| 信息邀请书 (RFI) | 先摸市场 |
| 建议邀请书 (RFP) | 范围复杂，要方案 |
| 报价邀请书 (RFQ) | 方案现成，**价格主因** |

签约后：更新计划（日期/资源/成本/质量/风险）→ 供应商变干系人 → 采购可贯穿全期 → 全部整合进项目运行。

## 四、变更：适应型 vs 预测型

| 类型 | 做法 | 别踩 |
|------|------|------|
| **适应型** | 新工作进产品待办；PO 持续排优；预算/进度紧时交完最高优即可收 | 进项 ≥ 完成量 → 项目拖死不结束 |
| **预测型** | 仅批准变更进范围基准；配人/资源/进度/预算；评估新风险；走 CCB | 口头改基准、未评估就实施 |

## 五、学习与知识

| | 经验教训 | 回顾 |
|--|----------|------|
| 焦点 | 以后哪能更好 | 即将迭代怎么改过程 |

| 知识 | 特征 | 怎么传 |
|------|------|--------|
| **显性** | 可编撰（字/图/数） | 人连信息：手册、登记册、库 |
| **隐性** | 经验洞察难写 | 人连人：访谈、跟随、研讨 |

项目临时 → 知识易丢；要主动做知识转移。

## 六、交付绩效域

预期：对齐战略 · 交出启动时要的成果 · 时框内见收益 · 需求清晰 · 干系人接受满意。

### 关键定义

- **需求**：必须具备的条件/能力  
- **WBS**：全部工作范围的层级分解  
- **DoD**：可交付物可给客户用的检查清单  
- **质量**：特征满足需求的程度  
- **COQ**：预防 + 评估 + 内外部失败成本  

### 价值何时出现

- 支持分期发布 → **项目期间**即可交价值  
- 末期大包交付 → 部署后才大量出价值；收益测量可延续到项目后  

商业论证 / 精益画布对齐目标；授权文件用基准或高层路线图便于定期测量。

### 需求与范围

- 启发 ≠ 只访谈：还有数据、观察、缺陷日志等；要记录并征得同意。  
- 演变需求：原型/演示/故事板（迭代/适应型常见）。  
- 管不好 → 返工、蔓延、超支、延期。常设 BA / PO / 价值工程师盯。  
- 范围：说明书 + 验收标准；或 WBS；敏捷侧主题→史诗→特性→用户故事，细节放到最后责任时刻。

完成判定：验收/完成标准 · 技术绩效指标 / WBS 词典 · **DoD**。

### 完成漂移

市场/技术变了，「够好可发」目标也在动。盯 **目标实现率 vs 进度完成率**；拖越久离「完成」越远。

## 七、质量与变更成本

- 范围/需求 = 交什么；质量 = 达到什么绩效水平。  
- COQ：一致性（预防+评估）vs 非一致性（内/外失败）。**预防优于评估；越晚发现越贵。**  
- 前移质量（分析师跟设计/工程）压低后期变更成本。  

次优成果可能存在（试验性项目、市场窗口丢失）；有效管理减负面，无法消灭不确定性。

## 八、易错对照

| 题干信号 | 选这 | 别选那 |
|----------|------|--------|
| 适应型加需求 | 进待办 + PO 排优 | Sprint 内静默硬塞 / 不管吞吐 |
| 预测型改范围 | CR → 评估 → CCB | 口头答应改基准 |
| 要方案不是要比价 | RFP | 直接 RFQ |
| 知识难写清 | 人连人（访谈/跟随） | 只丢一份手册 |
| 特别沟通请求爆炸 | 回头补沟通规划 | 只加班做演示 |
| 缺陷越晚越贵 | 前移质量 / 预防 | 末尾集中返工 |
| 项目目标该关了 | 关闭、余资源退回 | 镀金加功能 |
