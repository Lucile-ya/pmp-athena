# 三十六种套路速查

> 骐迹精华版摘要。遇情景题先对号入座，再看选项。

| # | 套路 | 选这 | 别选那 |
|---|------|------|--------|
| 1 | 巨大困难/障碍 | 寻找替代/解决方案 | 自己拍具体技术细节 |
| 2 | 要不要开始/继续 | **商业论证** | 直接干或直接砍 |
| 3 | 新项目/新 PM/高层级 | 想**章程**（概要一切） | 当详细计划 |
| 4 | 变更批准前 | 影响→提交→分析→方案→CCB | 跳步直接干 |
| 5 | 变更批准后 | 更新日志→更新计划→通知→实施→确认 | 只实施不更新 |
| 6 | 变更永远不选 | — | 拒绝/忽略/拖延/直接改/直接更新计划 |
| 7 | 需求/范围出问题 | 走变更；计划二选一时选**变更管理计划** | 默默加范围 |
| 8 | 挣值 | 先列 PV/EV/AC…再套公式；TCPI=(BAC-EV)/(BAC-AC) | 乱套 |
| 9 | 冲突 | 默认**合作/面对**；有「立即/缓和」再换策略 | 第一步升级 |
| 10 | 团队组建/建设 | 职能经理→谈判；能力不足→培训 | 命令职能经理 |
| 11 | 有人对立/不配合 | **面对当事人**了解原因 | 背后告状式上报 |
| 12 | 质量 | 规划/QA(过程)/QC(成果)分清；担心质量→质量管理计划 | QA/QC 混用 |
| 13 | 沟通差 | 沟通管理计划 / 规划沟通 / 需求分析 | 上来换人 |
| 14 | 风险 | 可能→登记册流程；已发生→应急/权变+问题 | 写进风险管理计划细则 |
| 15 | 两难选择 | 先 **EMV** 再决策 | 拍脑袋 |
| 16 | 供应商争议 | 合同→谈判→ADR→调解仲裁→诉讼 | 跳过合同直接告 |
| 17 | 相关方不满 | 参与计划 / 管理参与 / 尽早参与 / 识别 | 只发邮件了事 |
| 18 | 意见不一致 | 引导式研讨/开会统一 | 强推一方 |
| 19 | 新相关方 | 更新登记册 + 沟通了解（先人后册看题） | 无视 |
| 20 | 相关方数量 N | 看题是否含 PM | 固定公式死记 |
| 21 | 收尾 | 验收后收尾；发起人可宣布结束 | 验收前硬收尾 |
| 22 | 阶段门 | 阶段结束/下阶段启动准则 | 混为一谈 |
| 23 | 具体问题 | 不改「程序性计划」本身 | 一有风险就改风险管理计划结构 |
| 24 | 下一步参考什么计划 | 对应该领域管理计划（风险→风险管理计划等） | 乱抓总计划 |
| 25 | 输入 vs 工具 | 「用什么技术」→工具；「依据什么」→输入 | 混淆 |
| 26 | 求助发起人 | 几乎不作为第一步 | 没方案就上报 |
| 27 | 开工会议 | 计划批准后、执行前 | 规划前乱开 |
| 28 | 万能公式 | 主动；先确认事实→分析影响→计划→执行 | 等、拖、空汇报 |
| 29 | 其他 PM | 协商影响，不命令 | 「让他把人给你」 |
| 30 | 发起人乱指挥执行 | 用数据和计划沟通边界 | 硬顶或盲从无记录 |
| 31 | 利益冲突 | 非生死→利客户/用户；生死→发起人 | 私自偏袒 |
| 32 | 排序类工具 | 风险矩阵/帕累托/名义组/优先矩阵 | 张冠李戴 |
| 33 | 统计类 | 问卷/参数估算/实验设计/EMV | — |
| 34 | 估算 | 类比粗、参数公式、三点不确定、自下而上准 | 场景错配 |
| 35 | 权限边界 | 不做无权/无关事 | 越权改章程 |
| 36 | 问题日志 vs 风险册 | 已发生问题→问题日志；可能→风险册 | 混用 |

**加餐：想「多」了就停——回到题干问法（First/Next/Best）。**
