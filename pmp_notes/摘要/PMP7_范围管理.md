# PMP7 范围管理

> 来源：骐迹教育第 7 讲。镀金 vs 蔓延、WBS、需求跟踪——Process 高频。

## 一、镀金 vs 范围蔓延

| | 镀金 Gold Plating | 范围蔓延 Scope Creep |
|--|-------------------|----------------------|
| 含义 | 团队主动加「更好」功能，未经批准 | 未走变更控制，范围一点点变大 |
| 态度 | **禁止** | **禁止** |
| 正确 | 只做已批准范围 | 变更 → 评估 → 批准 |

**口诀：没批准的加功能，镀金蔓延都姓错。**

## 二、范围管理过程（骨架）

| 过程 | 一句话 | 关键输出 |
|------|--------|----------|
| 规划范围管理 | 如何定义、确认、控制范围 | 范围管理计划、需求管理计划 |
| 收集需求 | 要什么、验收标准 | 需求文件、需求跟踪矩阵 |
| 定义范围 | 边界写清 | 项目范围说明书 |
| 创建 WBS | 可交付成果分解 | 范围基准（WBS+词典+说明书） |
| 确认范围 | 正式验收可交付成果 | 验收的可交付成果 |
| 控制范围 | 监控范围基准，管变更 | 工作绩效信息、变更请求 |

## 三、收集需求工具速记

| 工具 | 用途 |
|------|------|
| 访谈 | 一对一/多对多；可拿机密信息 |
| 头脑风暴 / 焦点小组 | 创意与群体讨论 |
| 问卷调查 | 大量干系人快速收集 |
| 标杆对照 | 跨行业/项目对标 |
| 观察/交谈（工作跟随） | 看业务专家怎么干活 |
| 原型法 | 早反馈 |
| 亲和图 | 大量创意归类 |
| 多标准决策分析 MCDM | 标准加权打分排序 |
| 系统交互图 | 产品与外部系统边界 |
| 需求跟踪矩阵 | 需求↔设计/测试/交付；管变更框架 |

## 四、WBS 要点

1. 面向**可交付成果**（名词），不是活动清单  
2. **100% 原则**：下层之和 = 上层，充分且必要  
3. 可不平衡：不同分支层数可不同  
4. 越细越好管但管理成本↑，要平衡  
5. **项目管理工作**要编进 WBS  
6. WBS 词典：账户编码、描述、假设制约、责任组织、里程碑、资源、成本、质量、验收标准等  

**范围基准 = 范围说明书 + WBS + WBS 词典**

## 五、确认 vs 控制

| | 确认范围 | 控制范围 |
|--|----------|----------|
| 焦点 | 与客户/发起人**验收** | 对照基准管偏差与变更 |
| 工具 | 检查/审查 | 偏差分析、趋势分析 |

## 六、易错对照

| 题干信号 | 选这 | 别选那 |
|----------|------|--------|
| 团队悄悄加功能 | 制止镀金 | 表扬主动 |
| 客户口头加需求 | CR + 评估 | 直接进范围 |
| WBS 写成任务动词堆 | 改回交付物分解 | 当活动清单用 |
| 可交付物交了未验收 | 走确认范围 | 直接关项目 |
